# MARM software validation

Target: QCS8550 / ARM64 / Ubuntu 22.04, using a Bash terminal.
This headless test sends a deterministic image to the project's **actual RGB ROS
node**, then checks its color, object-pose and annotated-image outputs. It does
not open a camera or serial device, start an arm controller, run MoveIt planning,
move a robot, or validate NPU inference. Physical assembly and calibration remain
in the [task guide](AGORA_TASK_GUIDE.md).

Validated on QCS8550 / Ubuntu 22.04.2 / ROS 2 Humble on 2026-11-03.
The RGB node built in about 13 seconds; all three software checks passed.
Use a healthy APT/dpkg baseline and keep an existing ROS source configuration.

## 1. Check the environment

Choose your own absolute workspace. Keep the same terminal for the steps below.

```bash
export AGORA_WORKSPACE="$HOME/my-marm-demo"
export AGORA_SOC='QCS8550'

mkdir -p "$AGORA_WORKSPACE" &&
curl -fL https://raw.githubusercontent.com/APLUX-Agora/marm-vision-grasping/main/tools/check-environment.py \
  -o "$AGORA_WORKSPACE/check-environment.py" &&
python3 "$AGORA_WORKSPACE/check-environment.py" --soc "$AGORA_SOC" --ubuntu '22.04'
```

`CHECKED` means the check passed. `FAILED` means stop and fix the reported platform,
path, space or package-health requirement. Unfinished dpkg transactions or
inconsistent APT dependencies must be handled by the cloud administrator; the
check never runs automatic repair. `NEEDS_SETUP` means install the missing tools in step 3.
The SoC argument records the selected target; it does not prove BSP compatibility.
The check creates the workspace but does not install dependencies.

## 2. Get the code

```bash
git clone https://github.com/APLUX-Agora/marm-vision-grasping.git "$AGORA_WORKSPACE/code"
```

Skip clone if the directory already contains this project. Use `git pull --ff-only`
inside it when you choose to update.

## 3. Set up dependencies

Run the blocks in order. Stop at any failed command. Existing dependencies may be
kept. Use ROS's system Python, without a separate venv or pip replacement of NumPy.

**If step 1 reports `CHECKED ROS repository`, skip this first block.**
Keep the existing ROS source and signing key; installing a second source can
create a `Signed-By` conflict. Run this block only for `NEEDS_SETUP ROS repository`
after confirming there is no existing ROS source. See the
[ROS Humble installation guide](https://docs.ros.org/en/humble/Installation/Ubuntu-Install-Debs.html).

```bash
sudo apt-get update
sudo apt-get install -y curl git ca-certificates software-properties-common
sudo add-apt-repository -y universe
curl -fL https://github.com/ros-infrastructure/ros-apt-source/releases/download/1.3.0/ros2-apt-source_1.3.0.jammy_all.deb \
  -o "$AGORA_WORKSPACE/ros2-apt-source.deb"
sudo dpkg -i "$AGORA_WORKSPACE/ros2-apt-source.deb"
```

Install the headless test dependencies:

```bash
sudo apt-get update
sudo apt-get install -y --no-install-recommends build-essential cmake python3-colcon-common-extensions \
  python3-opencv python3-numpy libopencv-dev libyaml-cpp-dev \
  ros-humble-ros-base ros-humble-ament-cmake-auto \
  ros-humble-cv-bridge ros-humble-image-transport ros-humble-tf2-ros
```

Build only the RGB perception node:

```bash
source /opt/ros/humble/setup.bash
cd "$AGORA_WORKSPACE"
colcon build --base-paths "$AGORA_WORKSPACE/code/capture_image" \
  --packages-select capture_image --cmake-args \
  -DAGORA_SOFTWARE_ONLY=ON -DBUILD_TESTING=OFF
source "$AGORA_WORKSPACE/install/local_setup.bash"
```

Expected: `1 package finished` and an installed `rgb_detect_pose_node` executable.
This option excludes camera capture and ArUco executables; it does not replace the
RGB algorithm with a mock. Build, install and log directories stay in the workspace.

In a new terminal, repeat the two global declarations from step 1, then source
both ROS and the workspace setup files before running the test.

## 4. Get test resources

No HF model is needed: this path uses OpenCV color detection. The small software
fixtures are included in the code repository, separate from mechanical CAD files.

```bash
mkdir -p "$AGORA_WORKSPACE/resources"
cp -R "$AGORA_WORKSPACE/code/resources/software-test/." "$AGORA_WORKSPACE/resources/"
```

The camera geometry is synthetic and the input image is generated by the test.
**Do not use this file as calibration for a physical camera or robot.**

## 5. Run a test

```bash
source /opt/ros/humble/setup.bash
source "$AGORA_WORKSPACE/install/local_setup.bash"
/usr/bin/python3 "$AGORA_WORKSPACE/code/tools/test-software.py" \
  --resources "$AGORA_WORKSPACE/resources" \
  --output "$AGORA_WORKSPACE/results"
```

Expected terminal output:

```text
CHECKED color
CHECKED pose
CHECKED image
COMPLETED: .../results/result.json
```

The test supplies a red circle and a known synthetic camera transform. It verifies
the real node's red-class output, the expected pose near `[0.2, 0, 0]` metres, and
the annotated image. ROS communication is local-only, on a separate DDS domain
and private topic namespace. Only the child perception process is terminated when
the test finishes; it never kills other ROS processes.

Artifacts:

- `results/result.json`: checks, test pose and explicit software-only scope.
- `results/result.jpg`: annotated output; open it using the remote desktop if desired.
- `results/input.png`: generated input.
- `results/node.log`: node diagnostics. Inspect this first after `FAILED` or timeout.

A nonzero exit or missing `COMPLETED` means the software test did not pass. It is
not evidence of physical calibration, planning, grasping or hardware compatibility.
Continue to the task's local peripheral documents only when you have the actual
camera, controller and arm connected.
